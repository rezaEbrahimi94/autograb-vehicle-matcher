# Challenge audit

Basis: the original challenge in `supplied/README.md`, its data/input files, and the saved recruiter delivery record. This document maps requirements to implementation, not to a claim of perfect matching.

| Requirement                                                         | Evidence / disposition                                                                                                                                                                                                                               |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript or Python program                                        | Node/TypeScript CLI; locked dependencies and documented setup.                                                                                                                                                                                       |
| Local PostgreSQL; program queries both tables                       | `CatalogueStore.load()` queries `vehicle AS vi`; `counts()` left-joins `listing AS li` with parameterized IDs. Real SQL integration tests.                                                                                                           |
| Output for every supplied description                               | CLI streams all nonblank lines in order; each yields a match or explicit error. All 20 supplied descriptions are checked.                                                                                                                            |
| Vehicle ID/null and confidence 0–10                                 | String IDs, catalogue validation, bounded scores, contract tests. Operational errors remain errors.                                                                                                                                                  |
| Missing details reduce confidence; null confidence concerns absence | Heuristic confidence and low-certainty unresolved nulls are documented/tested. Not probability-calibrated.                                                                                                                                           |
| Most associated listings for equally likely matches                 | All semantic ties retained; live counts, zero-listing candidates and stable secondary ordering tested.                                                                                                                                               |
| Preserve SQL data                                                   | Original hashes checked; only the malformed PK declaration is corrected in memory during transactional setup.                                                                                                                                        |
| Consider 10k vehicles/100k listings                                 | Reusable indexes, bounded cache, SQL index, connection/query limits and disposable synthetic benchmark.                                                                                                                                              |
| Accuracy > cost > latency                                           | Measured failures are reported; no forced 100% claim. No external inference spend; latency/cost caveats explicit.                                                                                                                                    |
| Maintainability/data integrity                                      | One matcher, separate SQL/adapters, shared runtime contracts, strict types/typed lint, validated SQL/configuration, sanitized errors, repeatable setup, CI, integration tests and fingerprints. Grammar complexity remains a maintenance limitation. |
| Document personal and agent decisions/assets                        | `AI_ASSISTANCE.md`, assumptions, engineering scope and validation.                                                                                                                                                                                   |
| Delivery                                                            | Recruiter accepts a private repository shared with `frediy` and `raphydaphy`, or ZIP reply. The user subsequently chose public GitHub delivery; publication/access and the submission email remain delivery steps.                                   |
